Arbitrum documentation portal — a Next.js 16 / Fumadocs migration of [`OffchainLabs/arbitrum-docs`](https://github.com/OffchainLabs/arbitrum-docs) off Docusaurus. Serves English MDX docs (single locale; i18n was removed 2026-08-18). Phase 0 MVP: single-committer. CI landed 2026-08-17 (`.github/workflows/`); the repo is linked to the Vercel project `fumadocs-test`.

## Commands

```bash
pnpm install        # runs `fumadocs-mdx` postinstall → regenerates .source/
pnpm dev            # http://localhost:3000
pnpm types:check    # fumadocs-mdx && next typegen && tsc --noEmit — the verification gate
pnpm build          # next build --experimental-build-mode=compile
pnpm start          # serve the production build
pnpm partials:catalog  # regenerate content/partials/CATALOG.md + manifest.json
pnpm partials:check    # validate partials: include/import resolution, no routing leak, catalog freshness
pnpm test              # node --test over scripts/**/*.test.mjs (11 files)
pnpm check-links       # broken internal doc links
pnpm content:lint      # MDX structural defects (stray :::, admonition shape)
pnpm images:check      # report unreachable remote images (exit 1 only with --strict)
pnpm images:presence   # offline gate: fail on a markdown image with a remote src
pnpm vars:check        # every <Var name> resolves in content/vars.json
pnpm nav:check         # meta.json nav integrity
pnpm references:check  # glossary ids + <Reference> targets
pnpm drift             # compare content tree against upstream arbitrum-docs
pnpm redirects:legacy  # regenerate the legacy docs.arbitrum.io redirect map
pnpm redirects:check   # every redirect destination is a real page (needs `pnpm dev` running)
pnpm format:check      # prettier
pnpm precompiles:check # precompile tables match the pinned Nitro refs (--check = no writes)
pnpm contracts:generate # regenerate the contract-address partial from @arbitrum/sdk + scripts/data/
pnpm contracts:check   # same, but exit 1 with a line diff when the committed partial is stale (blocking gate)
pnpm cli:generate      # regenerate the Nitro CLI flags page from the pinned Nitro tag's Go source
pnpm cli:check         # same, but exit 1 with a line diff when the committed page is stale
pnpm nitro:check-release  # bump the pinned Nitro release in content/vars.json + hardcoded image tags in content/
```

- **CI runs on push and PR to `main` ([`.github/workflows/ci.yml`](.github/workflows/ci.yml)) in three jobs — only the first one blocks.** A green PR does not mean the content is clean: ten checks block, four report and pass anyway.
  - **`Gates` (blocking):** `types:check`, `test`, `vars:check`, `nav:check`, `partials:check`, `node scripts/versioned-docs-check.mjs`, `references:check`, `images:presence`, `check-links`, `contracts:check`. Fumadocs has no `onBrokenLinks: 'throw'`, so `check-links` supplies it — `pnpm build` now chains it ahead of `next build`, which fails the Vercel deploy on a broken link as well. It does **not** validate anchors, so a live page with a dead `#anchor` still passes; verify those in a browser.
  - **`Content debt` (non-blocking):** `format:check`, `content:lint`, `precompiles:check` — each marked `continue-on-error`. The first two still fail on pre-existing debt and the job comment records the counts as of the last update; **promote one of those two into `Gates` once its count reaches zero.** That promotion is the point of the split — the tier is a backlog, not a policy. `precompiles:check` is here for a different reason and reaching zero would not promote it: it is already green, but it fetches ~30 Solidity sources from `raw.githubusercontent` per run, so a GitHub blip reddens it for reasons unrelated to the change under review (the same argument that keeps `Build` non-blocking). Losing the network dependency is what would promote it.
  - **`Build` (non-blocking):** `pnpm build`. It catches MDX compile errors that `types:check` cannot see. It was made non-blocking because the MDX image pipeline fetched remote images at build time, so a dead third-party URL turned it red for reasons unrelated to the change under review. **That reason is gone** (FS-2681): `source.config.ts` sets `remarkImageOptions: { external: false }`, so the build never touches the network for images. Promoting this job into `Gates` is now possible and wants its own change.
- **A Husky pre-commit hook (`.husky/pre-commit`, config in `.lintstagedrc.mjs`) runs on every `git commit` and is a third tier, separate from the two CI tiers above.** It formats staged files with Prettier (except `meta.json`, generator output that Prettier would fight with `pnpm move-doc` on every run), runs `content:lint` on staged `content/**/*.mdx` but only for the rules already at zero findings repo-wide (`A1`, `A3`, `A4`; not `A2`/`A5`, which are the reason `content:lint` is still non-blocking in CI), and runs one full `pnpm types:check` when a `.ts`/`.tsx` file is staged, which is expensive (regenerates `.source/`, runs `next typegen`, then type-checks the whole project) even for a one-line change. Prettier and content-lint run as one sequential array entry for `.mdx`, not two separate glob entries, because lint-staged runs separate glob entries concurrently by default and the two would otherwise race on the same file. It skips entirely when `CI=true` or `HUSKY=0`. See [The gates](INTERNALS.md#the-gates) and [The local pre-commit hook](INTERNALS.md#the-local-pre-commit-hook) for the full reasoning.
- **`cli:check`, `redirects:legacy`, `redirects:check` and the network mode of `images:check` run nowhere automatically** — invoke them by hand. `drift` is worth running by hand for a local check but is no longer manual-only: the `drift` job in `upstream-refresh.yml` runs it weekly and maintains an issue from the result. `redirects:check` cannot run in CI as-is: it reads `/llms.txt` off a running site, because no plain-node script can import `lib/source` (neither the `collections/*` alias nor TypeScript resolves — the same wall `versioned-docs-check` hits, which is why that one text-parses `lib/versions.ts`). Point it at a Vercel preview with `--base-url` to check a PR. `images:check` requests third-party hosts, so its result depends on somebody else's uptime; its offline sibling `images:presence` does run in CI. `types:check` regenerates the collection, generates Next types, then type-checks. `build` runs `versioned-docs-check` then `check-links` first.
- **`drift` finds the upstream checkout itself** via `scripts/lib/upstream-tree.mjs` reading `scripts/data/upstream.config.json`: `--tree-a` (the docs tree, relative to the cwd), then `UPSTREAM_DOCS_REPO` (the repo root, relative to the cwd), then `repo`, then `probePaths` (both relative to **this repo's root**, so they work from a git worktree as well as the main checkout). Clone `arbitrum-docs` beside this repo and `pnpm drift` needs no arguments. **The freshness guard refuses to run against a clone last fetched more than 24 hours ago**, or one behind its upstream branch: a stale baseline does not fail loudly, it silently under-reports, because everything upstream changed since the last fetch looks identical to ours. Run `git -C ../arbitrum-docs fetch` first. **Pairing runs over the whole tree at once** (`pairTrees` in `scripts/lib/tree-compare.mjs`): directory-qualified matches first, each claiming its local file, then the bare-slug fallback for the rest, never onto an already-claimed file. Upstream keeps a concept page and a how-to page under the same basename (`arbos`, `stf`, `batchposter`/`batch-poster`), and per-file resolution let the how-to steal the concept page's local counterpart, producing three bogus GUTTED ratios that hid three unported how-tos behind them. Do not go back to per-file resolution. **One local file pairs with at most one upstream page in both passes**; the only exception is a deliberate two-into-one port, which both upstream entries declare with `merge: true` in `RENAME_MAP`. Three mechanisms change what the report says and they mean different things: `RENAME_MAP` in `scripts/lib/tree-compare.mjs` pairs a page ported under a new name (so it gets compared — the opposite of suppression); `absentAllowlist` in the config exempts a page deliberately never ported; `guttedAllowlist` exempts a page that **was** ported at parity, where the 70% ratio is only counting Docusaurus `import` lines and inline grid boilerplate. The two allowlists stay separate so an exemption earned for one reason cannot quietly cover the other. Every entry carries its reason, every `guttedAllowlist` entry names its local counterpart, drift lists what it suppressed under `ALLOWED`, and tests pin both lists and assert every `RENAME_MAP` target and `local` path still resolves to a real file, so growing a list is a reviewed act and an entry that rots into a no-op fails the suite instead of silently regrowing a false positive. **Exemptions expire.** Each entry records `reviewedUpstreamSha`, the git blob hash of the upstream page when a human granted it; drift recomputes that hash and re-flags the pair as `STALE-ALLOWLIST` (failing the run) once upstream edits the page, because the judgement was about one version of a page and not the page forever. A missing hash counts as stale. To clear one, re-read both pages and update the hash with `git -C ../arbitrum-docs hash-object docs/<path>`, or drop the entry.
- **`upstream-refresh.yml`** runs Mondays 08:00 UTC (and on `workflow_dispatch`) in two independent jobs. **`refresh`**: `nitro:check-release`, then `precompiles:generate`, `contracts:generate` and `cli:generate`, then opens `automated/upstream-refresh` as a PR if anything changed. It installs no Go or Rust toolchain, which is why `cli:generate` parses Nitro's Go source rather than running `nitro --help`. **`drift`**: clones `arbitrum-docs` (`--filter=blob:none`, then an explicit `git fetch` so `lib/git-freshness.mjs` accepts the baseline), runs `scripts/upstream-drift.mjs` against it, and keeps one issue titled "Upstream drift" in sync — body replaced while anything is absent or gutted, commented and closed when the report is empty. **The `drift` job is deleted at cutover (plan M-52).** It never writes to `main`, and no-ops when the tree is clean.
- **`types:check` proves the schema, not the render.** It exits 0 on pages that serve literal `:::`, `undefined`, or HTTP 500. Confirm content changes in a browser on `http://localhost:3000` — on `127.0.0.1` React does not hydrate and every component looks broken.
- **Node 22 LTS only** (`>=22 <23`), pnpm 10. Other Node majors are rejected by `engines`. Three places state it and must agree: `engines.node` in `package.json`, the `.node-version` file at the repo root (`22` — Vercel, nvm, fnm and asdf all read it), and the **Vercel project's Node.js Version setting, which must be set to 22.x by hand**. `.node-version` pins the build; the project setting is what the deployed functions run on, and a mismatch between them is reported nowhere. Locally, develop on Node 22 via `nvm use 22` in this directory; nvm reads `.node-version`, so no argument is needed. Never work around `engines` with `--ignore-engines`.
- The `.source/` directory is generated by `fumadocs-mdx` (postinstall / `types:check` / build). Never hand-edit it; regenerate instead.

## Architecture

**Build → render pipeline** (understanding it requires reading `source.config.ts`, `lib/source.ts`, and `app/docs/[[...slug]]/page.tsx` together):

1. `fumadocs-mdx` scans `content/docs/**`, validates every page's frontmatter against the Zod schema in `source.config.ts`, and emits the `.source/` collection.
2. `lib/source.ts` runs Fumadocs `loader()` over that collection with the icons plugin → the exported `source` object.
3. Route handlers read `source`: `app/docs/[[...slug]]/page.tsx` renders pages; the `llms.txt`, `llms-full.txt`, `llms.mdx/`, and `og/` routes all derive from the same `source`. Change the content model in one place and every consumer follows.

**`source` is a deliberate choke point — treat `source.config.ts` + `lib/source.ts` as one unit.** Seven files under `app/` import it (five routes, the docs page, the docs layout) and nothing else reads content:

- `docs.toFumadocsSource()` is the **only** adapter for `.source/`. Never build a second read path.
- `baseUrl` is an argument to the single `loader()` call. A second loader would restate it and silently drift page URLs.
- Helpers are typed `(typeof source)['$inferPage']`, so editing the frontmatter schema re-types every helper and every consumer at once.
- `postprocess.includeProcessedMarkdown: true` is what makes `getLLMText()`'s `page.data.getText('processed')` work — remove it and the `llms*` routes break, far from where the flag lives.
- Put URL derivation next to `source` (`getPageImage`, `getPageMarkdownUrl`, `getLLMText`), not in routes.
- **Server-only.** Never import `lib/source` — or a constant that transitively pulls it — from a client component; it drags the compiled collection into the browser bundle (one such import cost a 24 MB chunk on every docs page). No gate catches this.

**Frontmatter contract (enforced at build).** `source.config.ts` extends the Fumadocs page schema so every non-partial `.mdx` page **must** have `title`, `description`, `content_type`, `author`, `sme`. `content_type` is a fixed enum: `how-to | concept | quickstart | tutorial | reference | troubleshooting | faq`. Optional: `sidebar_label`, `user_story`, `draft`. A missing/invalid field fails `types:check` and `build` — this is the primary reason a build breaks after adding content.

**Last modified dates.** The `lastModified` option on the `docs` and `docsVersions` collections makes `fumadocs-mdx` read each file's date from git; `app/docs/[[...slug]]/page.tsx` prints it as "Last updated on …" under the description. It is **not** frontmatter, so never add a date field to a page. The option is gated behind `hasFullGitHistory()` in `source.config.ts`, because a shallow clone grafts its oldest commit as a parentless root and git then reports that commit as adding every file under it (measured at `--depth=10`: 430 of ~450 pages stamped with one boundary commit that touched nothing). No dates beat wrong dates everywhere, so nothing is resolved. **Never express that as `lastModified: false`**: the field exists on the generated `DocData` type only while the option is truthy, so `false` deletes it and the docs page fails `types:check` with TS2339 in any shallow checkout, CI included. The guard picks between `true` and a resolver that returns `undefined`, both truthy, so the type never moves. **Vercel clones at depth 10, so production shows no dates until `VERCEL_DEEP_CLONE=true` is set in the project's environment variables.** Display is formatted in UTC for deterministic output; the `<time dateTime>` attribute carries the exact instant. See [INTERNALS](INTERNALS.md#last-modified-dates).

**Page metadata.** `generateMetadata` in the docs page emits title, description, the OG image from the `og/` route, `alternates.canonical`, and `twitter` (`summary_large_image`, `@arbitrum`). The canonical uses `page.url`, which has no query string, so `?v=` archived views canonicalize to the live page. **Every absolute URL in a page's metadata comes from `getSiteUrl()` in `lib/shared.ts`**: `NEXT_PUBLIC_SITE_URL`, localhost outside production, and a **throw** when `VERCEL_ENV`/`NEXT_PUBLIC_VERCEL_ENV` is `production` and the variable is unset, or when a configured value does not parse as an absolute URL. `NEXT_PUBLIC_*` is inlined at build time, so without that throw a misconfigured production build ships every page with a canonical pointing at localhost, which is worse than none and invisible on the running site. **The rule itself lives in `lib/site-url.mjs`, in plain JavaScript, and `next.config.mjs` imports it.** That indirection is the enforcement: `pnpm build` never evaluates a page or layout module (`--experimental-build-mode=compile` plus an empty `generateStaticParams`), so the helper's throw does not fire during a build and the config file, the first thing the build does evaluate, is what actually fails it. One module means the enforcing copy and the tested copy are the same copy; never restate the condition in `next.config.mjs` by hand. `app/layout.tsx` also calls `getSiteUrl()` at module scope for `metadataBase`, as a backstop for anything reached outside a build. The helper imports nothing but that rule module, and must stay that way: `app/sitemap.ts` and `app/robots.ts` use it too, and anything heavier there would drag `lib/source` toward a client bundle. Covered by `scripts/lib/site-url.test.mjs`. **`RequestUpdateLink` is the one deliberate exception**: it reads `NEXT_PUBLIC_SITE_URL` directly and falls back to the site-relative path, because its URL goes into the body of a GitHub issue a human reads, where `/docs/stylus/quickstart` is more useful than a localhost URL. In production the two agree, since the build now fails without the variable. `app/(home)/page.tsx` has no canonical.

**Partials (registry model).** Reusable `_`-prefixed fragments live in **`content/partials/`** — outside the doc collection `dir` entirely, so they can never be routed (no glob exclusion needed). Two consumption paths, both tracked by the tooling:

- **`<include>` directive** (build-time splice). Doc→partial includes use the root-anchored `<include cwd>content/partials/…</include>` form, so moving a page never breaks its includes. **Partial→partial includes must be file-relative** (`<include>../x.mdx</include>`) — a partial may be compiled outside the docs pipeline when ESM-imported, where fumadocs-mdx's `cwd` context is undefined and crashes. `partials-check` enforces this.
- **ESM import** as an MDX component module: `import X from '@/content/partials/…/_x.mdx'`. Supported by the tooling (`scripts/lib/partials.mjs` scans the importer roots) but **currently used by no component** — the last consumer, `FloatingHoverModal`, was deleted as dead code. See the [README](README.md) for the shape.

**Discoverability: before writing a banner, note, config table, or troubleshooting block, search [`content/partials/CATALOG.md`](content/partials/CATALOG.md)** (⌘F by intent) and reuse the partial instead of duplicating prose. `CATALOG.md` + `manifest.json` (for agents) are generated — never hand-edit. Curate titles/summaries/tags in the optional `content/partials/registry.json` (`{ "content/partials/…/_x.mdx": { "summary": "…", "tags": ["…"], "scope": "neutral|localized" } }`). Partials carry no frontmatter (`<include>` strips it; the lint flags vestigial frontmatter).

**Two partials are generated, not written.** `content/partials/precompile-tables/*.mdx` (`pnpm precompiles:generate`) and `content/partials/_reference-arbitrum-contract-addresses-partial.mdx` (`pnpm contracts:generate`, sourced from the `@arbitrum/sdk` network registry plus `scripts/data/contract-addresses.data.mjs`, every address EIP-55 checksummed because `<AddressExplorerLink>` throws on a bad checksum). Both carry a do-not-edit marker. Edit the generator or its data file, never the `.mdx`.

Design: [`.claude/docs/superpowers/specs/2026-07-09-partials-registry-design.md`](.claude/docs/superpowers/specs/2026-07-09-partials-registry-design.md).

**Routing.** Single locale, no i18n: pages live directly under `content/docs/...` and serve at `/docs/...`. There is no `[lang]` route segment and no locale middleware; `lib/i18n.ts` was deleted 2026-08-18 along with the `ja` and `zh-CN` trees. `proxy.ts` now does exactly three things: (1) **request tracking** for markdown and `llms*.txt` fetches, which runs *before* the bypass list, (2) an explicit **bypass list** of routes served verbatim (`/_next/`, `/img/`, `/favicon.ico`, `/sitemap.xml`, `/robots.txt`, `/llms*`, `/og/`, `/api/`), and (3) `.md`-suffix rewrites plus `Accept: text/markdown` content negotiation to the markdown route. **A new top-level route still belongs in that bypass list** or markdown negotiation will try to rewrite it. Re-adding localization means restoring `defineI18n`, the `i18n` argument to `loader()`, a `[lang]` segment, and `createI18nMiddleware`.

**Request tracking.** `proxy.ts` sends a PostHog `llms_file_fetched` event for `/llms.txt`, `/llms-full.txt`, `/docs/<slug>.md`, `/llms.mdx/docs/<slug>/content.md`, and `Accept: text/markdown` negotiation on a `/docs` URL. All three markdown shapes normalize to the canonical `/docs/<slug>.md`; each request is counted once, because a rewrite does not re-enter the proxy. **Only when `VERCEL_ENV === 'production'`**, so nothing fires locally or on preview, and no key is needed to run the app. Key is `NEXT_PUBLIC_POSTHOG_KEY` (same publishable token `lib/posthog.ts` uses). The capture goes through `event.waitUntil()` on the `NextFetchEvent` Next passes as the proxy's second argument, and every failure is swallowed and logged, so tracking can never break a response. A **rejected** event needs its own `response.ok` check to be one of those logged failures: `fetch` rejects only on a network failure, so a 401 from a revoked token resolves normally and would otherwise read as no traffic at all. **Do not swap that for `waitUntil` from `@vercel/functions`**: that one resolves the request context through `globalThis[Symbol.for('@vercel/request-context')]`, which Next 16 does not set (it sets `@next/request-context`), so it returns `{}` and drops the promise silently. The IP is hashed with a UTC daily salt into the `distinct_id`, which prevents linking a reader across days but is **not** anonymisation: the salt is a public date, so an IPv4 hash is brute-forceable. Requests with no `x-forwarded-for` get a per-request random id rather than collapsing into one shared person, and **that branch alone sets `$process_person_profile: false`**, since a unique id per request would otherwise mint a useless person profile per request; the hashed path keeps its profile, which is the point of the stable daily id. The negotiation branch applies **exactly the condition the rewrite applies and no more** (the rewrite is `/docs{/*path}`, which matches dotted slugs), so a dotted slug is not served markdown while recording nothing; the cost is that a request the proxy rewrote to a 404 is still tracked, which is the right way round because an undercount is invisible. `$current_url` takes its origin from `getSiteUrl()`, not `request.nextUrl.origin`, so the `*.vercel.app` alias cannot split one page into two series. Classification lives in `lib/llms-tracking.ts`, which is **deliberately import-free** so `scripts/lib/llms-tracking.test.mjs` can import it directly under `node --test` (Node 22 strips types natively) and `pnpm test` exercises the real module rather than a copy. Its local copies of `docsRoute`/`docsContentRoute` are pinned to `lib/shared.ts` by two `satisfies` statements in `proxy.ts`, so drift fails `types:check`.

**Sitemap and robots.** `app/sitemap.ts` and `app/robots.ts` are Next **metadata routes** (file conventions, so no `route.ts` and no hand-written XML; neither sets `revalidate`, which would only restate the default). The sitemap derives one entry per page from `source.getPages()`, plus the home page `/` which is not in the doc collection. There is nothing to exclude: partials, `content/_versions/`, and the glossary all live outside the doc collection `dir`, so upstream's `nonCanonicalRoutePatterns` has no equivalent here. `<lastmod>` is emitted per page from `page.data.lastModified`, which the full-git-history probe leaves `undefined` in a shallow checkout; the tag is then simply absent, which is valid. `app/robots.ts` emits the non-standard `Content-Signal: search=yes, ai-input=yes, ai-train=no` through a rule's `other` field (Next 16.3.0+). **Both take their origin from `getSiteUrl()`**, the same helper behind `metadataBase` and the docs page canonical, so a production build with no `NEXT_PUBLIC_SITE_URL` fails instead of silently shipping a sitemap pointing at localhost. See [INTERNALS](INTERNALS.md#sitemapxml-and-robotstxt).

**Global variables.** Writer-edited values live in `content/vars.json`, validated by the Zod schema in `content/vars.ts`. Most are rendered in MDX via `<Var name="..." />`; a minority are read by code instead and appear in no `.mdx` file, which is why `pnpm vars:check` reports them as "configured but unreferenced". That warning is expected for those keys and is not a defect. A bad value fails at module load. **`<Var>` does not evaluate inside a fenced code block or an inline code span.** It ships as the literal tag text, and neither `vars:check` nor `types:check` sees it, since both only prove the key exists, not where it is used. `content:lint` rule A6 is the gate. Usually the value was never code and dropping the backticks is the fix; a copy-pasteable `docker run` command genuinely needs the value spelled out, so hardcode it there and put the live `<Var>` in the prose beside it. `pnpm nitro:check-release` then keeps those copies current by rewriting the **outgoing** `latestNitroNodeImage` value when it bumps the variable, but **only in a file carrying the opt-in marker `{/* sync-with-var: latestNitroNodeImage */}`**. The marker is not optional ceremony: matching the outgoing value alone looks safe but is not, because `content/docs/run-a-node/arbos-releases/*.mdx` pin the minimum Nitro version per ArbOS release and `arbos61.mdx` pins the value that is *currently* the latest image, so an unmarked rewrite would make it claim ArbOS 61 requires a build published after it. Never add the marker to a page that states a Nitro version historically.

**Announcement banner.** The bar above the navbar is Fumadocs' `Banner`, rendered by `app/layout.tsx` inside `RootProvider` and above `{children}`, which is what puts it above every layout's header. Five `vars.json` keys drive it and **none of them is a `<Var>` substitution** (see above): `announcementEnabled`, `announcementText`, `announcementLinkText`, `announcementLinkHref`, `announcementId`. Three constraints, each enforced somewhere different:
- `announcementLinkHref` is gated by `pnpm vars:check` (rule in `scripts/lib/announcement-link.mjs`): an `https` URL, or a root-absolute internal path resolving to a real page or a `public/` file. Relative hrefs are rejected, since the banner renders on every route. `check-links` walks MDX only and this value lives in JSON, so that check is the only thing standing between a typo and the most visible broken link on the site.
- `announcementId` must match `^[A-Za-z][A-Za-z0-9_-]*$` (schema). It reaches the DOM as an `id` and as a `#id` selector; a space or leading digit breaks dismissal silently. It is also the dismissal key, written to `localStorage` permanently, so **a new message needs a new id** or it stays hidden from everyone who dismissed the last one.
- The bar's height is fixed in `app/layout.tsx` (`3rem`, `4rem` below 640px) because `--fd-banner-height` feeds the sticky offsets. **No gate couples it to the text**, so a long `announcementText` overflows; the budget (roughly 140 characters including the link text) is stated in [README](README.md#announcement-banner). Full rationale in [INTERNALS](INTERNALS.md#announcement-banner).

**Partial versioning.** Archived pages live in `content/_versions/<id>/…` — a separate non-routed collection, outside `content/docs` for the same reason partials are. `lib/versions.ts` indexes them by path; only hand-registered pages are versioned. Spec: [`.claude/docs/superpowers/specs/2026-07-17-partial-versioning-design.md`](.claude/docs/superpowers/specs/2026-07-17-partial-versioning-design.md).

**Glossary / inline references.** `content/glossary/*.mdx` is a reference collection (`{ id, title, sortAs? }` — *not* the page contract), surfaced by `<Reference>` / `<Term>` / `<ReferenceList>` via the registry in `lib/references.ts`. New reference types add a collection plus one registry entry. Spec: [`.claude/docs/superpowers/specs/2026-07-10-references-glossary-design.md`](.claude/docs/superpowers/specs/2026-07-10-references-glossary-design.md).

**Custom MDX components.** `components/mdx.tsx` is the registry and the source of truth, so read it rather than trusting a list here. Implementations in `components/mdx/`; Fumadocs' `Accordion`/`Accordions` and `Tab`/`Tabs` are re-exported. Some names are aliases of the same component (`AEL` → `AddressExplorerLink`, `ImageWithCaption` → `ImageZoom`). Every Docusaurus widget the content uses is ported; there is no placeholder component. Add a component here to make it available in all MDX.

**Generated pages.** `content/docs/run-a-node/nitro/cli-flags-reference.mdx` is written by `pnpm cli:generate` from the Nitro source at the tag pinned as `nitroVersionTag` in `content/vars.json` (it materialises the pinned tag plus its go-ethereum submodule, where the `execution.rpc.*` flags live). Only the region between `{/* GENERATED:START */}` and `{/* GENERATED:END */}` is replaced — the frontmatter and any prose outside the markers are preserved, so the five required fields survive a regeneration. Flags whose default is not a static value (`util.GoMaxProcs()`) and flags registered with `f.Var` are declared in `scripts/data/nitro-cli-reference.data.mjs`; anything else the reader cannot evaluate fails the run rather than rendering a blank cell.

**Sidebar ordering** is controlled by `meta.json` in each content directory, not by file names.

## Known trade-off (not a bug)

`app/docs/[[...slug]]/page.tsx` has `generateStaticParams` return `[]`, deliberately disabling static prerendering (ISR-on-first-request) to work around a Next 16.2.6 prerender crash — hence `build` uses `--experimental-build-mode=compile`. The inline comment documents the restore path; don't "fix" it without addressing that.

## Conventions

- Theme tokens are `--color-fd-*` (Fumadocs). Never use `--ifm-*` (legacy Docusaurus).
- `lib/shared.ts` holds route constants (`docsRoute`, `docsImageRoute`, `docsContentRoute`) and the git config used for edit links — reference these rather than hardcoding paths.
- **Redirects.** All of them live in `redirects.config.mjs`, consumed by `next.config.mjs`. Both blocks in it are generated — `pnpm move-doc` writes moved-page entries between the `AUTO-GENERATED` markers, `pnpm redirects:legacy` writes `redirects.legacy.mjs` — so never hand-edit it. `pnpm move-doc` also retargets the moved path in the two drift maps that name local paths, a `RENAME_MAP` value (including the `to` field of a `merge: true` entry) in `scripts/lib/tree-compare.mjs` and a `guttedAllowlist` entry's `local` field in `scripts/data/upstream.config.json`, via `scripts/lib/drift-maps.mjs`. That rewrite edits only inside the `RENAME_MAP` literal (a whole-file match would rewrite a `SECTION_MAP` value such as `'stylus'` and silently remap a whole upstream section), cross-checks its substitution count against the imported `RENAME_MAP` and throws rather than let a reformat make a miss look like "no entry", and runs last, writing both maps or neither. **It does not touch `MANUAL_DESTINATIONS`** in `scripts/lib/legacy-redirects.mjs`, so moving a page named there still fails `pnpm test` in a later PR; grep it for the old URL after a move (tracked as FS-2697, because fixing it properly means regenerating `redirects.legacy.mjs`, which needs the upstream checkout `move-doc` does not require). Next's `redirects()` runs **before** `proxy.ts`, so a redirected URL gets markdown negotiation on the destination, not the first hop. `redirects.legacy.mjs` is seeded from **two** inputs, both resolved by the same rules: upstream's own redirect sources (its `vercel.json`) and every canonical upstream page URL, derived from its `docs/` tree by `scripts/lib/upstream-pages.mjs` (strip `NN-` prefixes except date-like and version-like ones; `index`/`README`/folder-named files take the directory URL; frontmatter `slug` beats `id` beats file name; drop `sdk`, `api`, `hosted-pdfs`, `superpowers`, any `partials/` directory and anything `_`-prefixed; add `sidebars.js` `generated-index` landings that carry a slug). The second input exists because upstream served docs at `/` while this site serves them under `/docs`, so a canonical URL that was never a redirect source would otherwise 404 at cutover. Resolution order: `MANUAL_DESTINATIONS`, self-URL, section rename, exact frontmatter title (one local page carries the upstream title verbatim **and** one upstream page carried it; this sits ahead of the basename because the site pairs a `features/.../choose-X` "why" page with a `configuration/.../X` how-to and the basename kept picking the "why" half), unique basename (also required to be unique upstream), then `SECTION_LANDINGS` (the nearest live section, for a page this site has not ported, and last on purpose so it goes inert the moment that page lands). Both the title and basename rules decline on an upstream collision for the same reason: there the legacy path was doing the disambiguating, so a folded pair is a judgement and belongs in `MANUAL_DESTINATIONS`, not in an inference. A source that names a live route here is skipped and reported, never emitted, because Next's redirects beat the route. `MANUAL_DESTINATIONS` and `SECTION_LANDINGS` are hand-written, so `pnpm test` walks `content/docs` and asserts every non-external value in both still resolves — the generator only throws for an entry it happens to reach that run, so without the test an entry orphaned by `pnpm move-doc` rots silently into a redirect to a 404. Unresolvable legacy URLs are parked in `redirects.legacy.todo.json` rather than pointed at a plausible page: a redirect to the wrong page is worse than a 404, and `redirects:check` cannot catch one because the destination exists. **That file reached `[]` on 2026-08-31, stayed `[]` when canonical URLs were added on 2026-09-11, and is a tripwire, not a backlog** — a non-empty todo after `pnpm redirects:legacy` means upstream added a page or a redirect this site cannot resolve, so map it in `MANUAL_DESTINATIONS` (confirm the upstream page's frontmatter title against the local candidates) instead of leaving it parked. See [INTERNALS](INTERNALS.md#redirects).
- **Remote images: markdown syntax 500s, `<ImageZoom>` does not.** `source.config.ts` sets `remarkImageOptions: { external: false }`, so nothing measures a third-party image at build. A markdown image with a remote src (`![alt](https://…)`) resolves to `next/image`, which then has no `width` and throws `Image with src "…" is missing required "width" property`: **the page returns HTTP 500**, measured, not inferred. The same URL through `<ImageZoom src="https://…" />` renders fine, because that component is a plain `<img>` (live example: `content/docs/third-party-docs/Particle/particle.mdx`). Prefer committing the file under `public/` and referencing `/img/…`, which is the only form that is both reliable and optimized. Before this change a dead remote URL threw during compilation and 500ed **every** docs page, not just the page holding it (FS-2681). `pnpm images:presence` blocks the markdown case in CI; `pnpm images:check` sweeps for rot by hand. See [INTERNALS](INTERNALS.md#remote-images-are-never-fetched-at-build).
- **Image zoom.** `<ImageZoom>` resolves to the wrapper in `components/mdx/ImageZoom/` (plain `<img>` child; supports `caption`; no dimensions needed; no Next image optimization). To use Fumadocs' native component instead — for `_next/image` optimization — import it per file: `import { ImageZoom } from 'fumadocs-ui/components/image-zoom'` (shadows the wrapper for that file). The native component then requires `width`/`height` or the build fails; add `style={{ width: '100%', height: 'auto' }}` for responsiveness and drop `caption`. Live example: `content/docs/en/get-started/arbitrum-introduction.mdx`.
